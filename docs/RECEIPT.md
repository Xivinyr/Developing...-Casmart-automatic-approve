# 采购单据签收

签收使用独立的桌面入口和 `order_receipt.py`。首版一次处理一条明确指定的采购单据。现有分类清单记录工作表、起始行和商品，尚没有可与 Casmart 单据直接关联的编号。由本人选择清单记录并填写对应单号。

## 操作步骤

1. 先用腾讯网页选区或本地 XLSX 入口分类附件。若清单中缺发票，按附件说明补齐后选用新的输出清单。
2. 运行 `python main.py`，选择“采购单据签收”。打开该批分类输出里的 `manifest.json`，选中工作表和起始行，填写对应采购单据的完整单号。列表有多个编号列时，选实际对应的列。
3. 查看终端中列出的附件。默认要求订单截图、支付记录、发票、开箱实物图四类齐全。程序校验每个文件仍位于该条记录的目录，且实际格式、大小和哈希与清单一致。
4. 登录后，程序按完整单号扫描当前筛选条件下的分页。核对终端打印的单据编号、商品及其他列。商品名称由两边明确提供且不一致时，程序停止。若没有可用签收按钮，也会停止。
5. 输入窗口给出的 `上传 单号`。程序点击指定行的“签收”，重新核对新表单显示的单号，然后按页面上传区接收的类型上传附件。
6. 文件名和上传成功状态逐一核对后，在浏览器检查材料，再输入 `签收 单号`。程序点击一次最终签收，看到明确的网页提示才报告成功。任务窗口按回车关闭。

直接回车可取消当前确认。已上传后取消最终签收时，材料可能已在网站暂存。已有附件、上传失败、提示不明确或网页结构不符时，先在页面复核，避免重复上传或签收。

## 预检与页面支持

~~~powershell
python order_receipt.py --manifest "outputs\run-示例\manifest.json" --sheet-index 1 --row 2 --order-id SYN-123
~~~

命令默认仅检查本地记录与文件。加 `--check-list` 可完成登录并只读核对编号，不打开签收表单。加 `--execute` 后仍需要本人在两步输入完整确认语句。

网页需要能提供唯一的行内签收入口。在单据所在的 Casmart 页面或可识别的同源表单中，须显示相同类型的完整单号。支持一个接收全部材料的上传区，或明确标为“订单截图”“支付记录”“发票”“开箱实物图”的四个上传区。上传区必须接收对应格式。发票可用分类器保存的 PDF 或图片，PDF 被拒绝时保留原文件。

文件完成状态目前读取 Element UI、Ant Design 上传列表中的文件名与成功状态，或等价的明确文件状态。最终须看到新的“签收成功”或“签收完成”提示。独立新窗口、无法核对的表单、需另确认的弹窗、未提供逐文件结果的上传方式都暂停，后续依据实际网页调整。

## 验证范围

常规测试用分类器生成虚构资料，验证明确行号、同名商品隔离、单号匹配、路径与内容校验、上传状态和两步确认。另可启用断网 Edge 合成测试，使用真实的文件选择以及签收点击，仅对合成页面：

~~~powershell
python -B -m unittest discover -s tests
$env:CASMART_RECEIPT_BROWSER_TEST = '1'
$env:CASMART_TEST_EDGEDRIVER = 'C:\path\to\msedgedriver.exe'
python -B -m unittest discover -s tests -p test_order_receipt_browser.py -v
~~~

真实腾讯导出、真实 Casmart 附件接收格式、表单布局和线上签收结果仍待验收。先用明确单号和 `--check-list` 核对列表，再选择一笔待签收单据验证完整步骤。
