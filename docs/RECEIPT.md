# 采购单据签收

签收使用独立任务。输入是附件分类输出的一个批次文件夹，里面须有 manifest.json。网页商品名、分类清单商品名与该条记录的文件夹必须能唯一对应。工作表下的 row-000002-商品名 是分类器生成的目录结构。

## 操作步骤

1. 先用腾讯网页选区或本地 XLSX 分类附件。发票缺失时先补齐，再选新的批次。
2. 运行 `python main.py`，选「采购单据签收」和保存分类结果的批次文件夹。
3. 登录后，程序扫描当前筛选范围的全部分页。核对终端列出的商品和对应文件夹。有多个可签收的匹配时，选择本次处理的一项。
4. 输入「上传」。程序重新核对同名商品在网页仍唯一，打开该行的签收表单，再核对其中的商品名称。
5. 等每个文件都显示上传成功，在浏览器复核附件，再输入「签收」。收到明确的网页成功提示后任务才报告完成。

网页或所选批次中同名商品有多条记录时，该商品会跳过。只匹配完整名称，统一显示换行、空白与等价 Unicode 字符。程序同时检查实际目录名、路径、文件格式、大小和哈希，避免使用另一条记录的材料。若网页采用其他商品表头，可用 `--product-column` 指定。

默认要求订单截图、支付记录、发票和开箱实物图四类齐全。支持一个共用上传区，也支持按四种材料标明名称的独立上传区。PDF 若不被网页接受，先核对网页格式要求。已有附件、上传失败、表单商品无法核对或结果不明时，任务会停下来。取消最终签收时，已上传的附件可能还在网页暂存。

## 预检与验证

~~~powershell
# 本地查看能用的商品文件夹
python order_receipt.py --folder "outputs\run-示例"

# 登录并只读核对匹配结果
python order_receipt.py --folder "outputs\run-示例" --check-list
~~~

`--execute` 允许在核对并输入确认语句后上传及签收。`--manifest` 也可指向该目录的清单文件。

使用断网 Edge 的合成测试验证无单号列、商品与文件夹匹配、共用或分栏上传、上传状态和最终签收。真实腾讯导出及真实 Casmart 的实际表头、上传格式和签收回执仍待验收。
